# packages/ — Publishable Plugin Packages

**Generated:** 2026-05-06 | **Commit:** 10ae7625

## OVERVIEW

Package roots that OpenCode/npm consumers install. Implementation still lives in `src/`; package entries adapt it into package-level plugin products.

## STRUCTURE

```text
packages/
├── oh-my-opencode/           # Full plugin package
├── opencode-task-delegation/ # Standalone task delegation plugin
└── opencode-lsp-tools/       # Standalone LSP tools plugin
```

## PACKAGE CONTRACT

| File | Contract |
|------|----------|
| `package.json` | Public package metadata, root `.` export, `files: ["dist"]` |
| `src/index.ts` | OpenCode `Plugin` default export only |
| `dist/` | Generated by root `bun run build`; never hand-edit |

## WHERE TO LOOK

| Task | Location |
|------|----------|
| Full plugin package | `oh-my-opencode/` |
| Delegation-only package | `opencode-task-delegation/` |
| LSP-only package | `opencode-lsp-tools/` |
| Workspace build orchestration | Root `package.json` |
| Package unused-export entries | Root `knip.ts` workspaces |

## CONVENTIONS

- Each package exports only `.`; no `./tools`, `./agents`, or library subpaths.
- Package source should stay a thin `src/index.ts` adapter.
- Keep runtime implementation in `src/` until a package owns its own internal implementation boundary.
- Package manifests declare runtime deps; root declares workspace packages as `workspace:*` dev deps for local import QA.

## ANTI-PATTERNS

- Adding package-specific `tsconfig.json`, `bunfig.toml`, or `knip.ts` without a package-local test/build need.
- Publishing source files; `files` must remain `dist` only.
- Hand-editing generated `dist/` or `.types/` output.
- Duplicating root build commands in child docs.
